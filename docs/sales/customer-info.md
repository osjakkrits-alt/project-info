# Customer Info

## วัตถุประสงค์และขอบเขต

กำหนดข้อมูลลูกค้าและผู้ติดต่อสำหรับช่วง Sales ของ [Project Information Lifecycle](../project-information-lifecycle.md) เป็นโครงสร้างตั้งต้นที่ไม่ผูกกับระบบหรือเทคโนโลยีใด

ลูกค้าหนึ่งรายมีหลายผู้ติดต่อและหลาย Opportunity ได้ โดยเก็บขั้นตอนและสถานะการขายที่ Opportunity ตาม [Sales Status Flow](sales-status-flow.md)

## โครงสร้างและความสัมพันธ์

| ข้อมูล | ความหมายและความสัมพันธ์ |
| --- | --- |
| Customer / Account | องค์กรลูกค้าหรือผู้มุ่งหวัง เป็นข้อมูลกลางที่ใช้ร่วมกันระหว่างหลายงาน |
| Contact | ผู้ติดต่อที่เชื่อมกับ Customer พร้อมตำแหน่งและช่องทางติดต่อ |
| Opportunity | โอกาสขายหนึ่งงาน เชื่อมกับ Customer หนึ่งรายและผู้ติดต่อที่เกี่ยวข้อง |
| Opportunity Contact | ความสัมพันธ์ระหว่าง Opportunity กับ Contact ระบุบทบาทในงานนั้น เช่น ผู้ใช้งาน ผู้ประเมินเทคนิค ผู้ตัดสินใจ หรือฝ่ายจัดซื้อ |

ผู้ติดต่อหลักขององค์กรกับผู้ติดต่อหลักของแต่ละ Opportunity อาจเป็นคนละคน บทบาทในการตัดสินใจจึงต้องระบุแยกตามงาน

## ข้อมูล Customer

คำว่า “บังคับ” หมายถึงต้องมีเมื่อสร้างรายการ ส่วนข้อมูลเสริมเติมเมื่อทราบและเกี่ยวข้องกับงาน

| ข้อมูล | การจัดเก็บ | รายละเอียด |
| --- | --- | --- |
| Customer ID | บังคับ | รหัสอ้างอิงไม่ซ้ำและไม่เปลี่ยนตามชื่อองค์กร |
| ชื่อองค์กร | บังคับ | ชื่อที่ใช้ระบุตัวลูกค้า |
| Account owner | บังคับ | ผู้รับผิดชอบดูแลลูกค้าภายในทีม |
| Record status | บังคับ | Active หรือ Archived ใช้บอกสถานะข้อมูล ไม่ใช่ผลการขาย |
| ชื่อทางการ / ชื่อย่อ | เสริม | ชื่อเพิ่มเติมสำหรับค้นหาและตรวจข้อมูลซ้ำ |
| ประเภทธุรกิจ | เสริม | กลุ่มธุรกิจของลูกค้า |
| เว็บไซต์ | เสริม | เว็บไซต์หรือโดเมนองค์กร |
| ที่อยู่ | เสริม | ที่อยู่ที่เกี่ยวข้องกับการติดต่อหรือดำเนินงาน |
| ผู้ติดต่อหลัก | เสริม | อ้างอิง Contact ขององค์กรนี้ |
| ทีมที่เกี่ยวข้อง | เสริม | ผู้ร่วมดูแลลูกค้า |
| หมายเหตุ | เสริม | บริบทที่จำเป็น โดยข้อมูลเฉพาะงานให้เก็บที่ Opportunity |

## ข้อมูล Contact

| ข้อมูล | การจัดเก็บ | รายละเอียด |
| --- | --- | --- |
| Contact ID | บังคับ | รหัสผู้ติดต่อไม่ซ้ำ |
| Customer ID | บังคับ | องค์กรที่ผู้ติดต่อสังกัด |
| ชื่อผู้ติดต่อ | บังคับ | ชื่อที่ใช้ติดต่อ |
| ช่องทางติดต่อ | บังคับอย่างน้อยหนึ่งช่องทาง | อีเมล โทรศัพท์ หรือช่องทางอื่นที่ใช้ได้ |
| ตำแหน่ง / แผนก | เสริม | หน้าที่และหน่วยงานภายในองค์กร |
| ช่องทางที่สะดวก | เสริม | ช่องทางและช่วงเวลาที่เหมาะกับการติดต่อ |
| Record status | บังคับ | Active หรือ Inactive เช่น เมื่อย้ายออกจากองค์กร |
| หมายเหตุ | เสริม | บริบทที่จำเป็นต่อการติดต่อ |

ทั้ง Customer และ Contact ต้องมีผู้สร้าง วันที่สร้าง ผู้แก้ไขล่าสุด และวันที่แก้ไขล่าสุด

## Use cases

| กรณีใช้งาน | การทำงานและผลลัพธ์ |
| --- | --- |
| เพิ่มลูกค้าใหม่ | ค้นหารายการเดิมก่อน สร้าง Customer และกำหนดเจ้าของข้อมูล |
| เพิ่มผู้ติดต่อ | เชื่อม Contact กับ Customer และกำหนดผู้ติดต่อหลักเมื่อทราบ |
| เปิดโอกาสขาย | สร้าง Opportunity ใต้ Customer เดิม เลือกผู้ติดต่อและบทบาทเฉพาะงาน |
| ปรับข้อมูลหรือเปลี่ยนผู้ดูแล | แก้ข้อมูลพร้อมบันทึกประวัติผู้เปลี่ยน เวลา และค่าก่อน/หลัง |
| ผู้ติดต่อย้ายออก | เปลี่ยน Contact เป็น Inactive และเลือกผู้ติดต่อทดแทน โดยคงประวัติงานเดิม |
| พบข้อมูลลูกค้าซ้ำ | ตรวจยืนยันก่อนรวมข้อมูล ย้ายความสัมพันธ์ไปยังรายการหลักและเก็บรหัสเดิมไว้อ้างอิง |
| เลิกใช้งานข้อมูลลูกค้า | ตรวจ Opportunity ที่ยังเปิดและจัดการงานค้างก่อนเปลี่ยน Customer เป็น Archived |

## กติกาการจัดเก็บ

- ตรวจข้อมูลซ้ำจากชื่อองค์กร ชื่อทางการ และโดเมนประกอบกัน ไม่รวมข้อมูลอัตโนมัติจากชื่อคล้ายกันเพียงอย่างเดียว
- ตรวจ Contact ซ้ำภายในองค์กรจากชื่อและช่องทางติดต่อ อีเมลกลางอาจใช้ร่วมกันได้
- ข้อมูลเสริมที่ยังไม่ทราบให้เว้นว่างหรือแสดง “ยังไม่ทราบ” ไม่ใช้ข้อมูลสมมติแทนข้อมูลจริง
- อ้างอิง Customer และ Contact ด้วยรหัส เพื่อลดการคัดลอกข้อมูลซ้ำในแต่ละ Opportunity
- เก็บประวัติการเปลี่ยนแปลงสำคัญ รวมถึงการเปลี่ยนเจ้าของข้อมูล การรวมรายการ และการเก็บเข้าคลัง
- ไม่ลบข้อมูลที่มีประวัติการขายอ้างอิง และไม่เลือกข้อมูล Archived / Inactive สำหรับงานใหม่จนกว่าจะเปิดใช้งานอีกครั้ง
- เอกสารใน repository นี้เก็บเฉพาะโครงสร้างและตัวอย่าง placeholder ข้อมูลลูกค้าและช่องทางติดต่อจริงให้เก็บในระบบที่ทีมกำหนด
