# App Layout

## Purpose and scope

กำหนดโครงหน้าเว็บที่ใช้ร่วมกันสำหรับ Frontend prototype ได้แก่ Sidebar, Header, Content area และตัวสลับภาษาไทย/อังกฤษ ใช้หน้า Customers เป็นตัวอย่างหลักเพื่อประเมินเมนูและแนวธีมก่อนพัฒนารายละเอียดหน้าจอ

รอบนี้ใช้ข้อมูลจำลองและการนำทางระหว่างหน้าตัวอย่าง ยังไม่เชื่อม Backend / PostgreSQL หรือสร้างฟอร์มธุรกิจเต็มรูปแบบ เอกสารนี้ยังไม่กำหนด Framework หรือสร้างโปรแกรม

เอกสารอ้างอิง:

- [Architecture](../architecture.md): ส่วนประกอบระบบและขอบเขต POC
- [Conventions](../conventions.md): ข้อตกลงการพัฒนาและการรองรับสองภาษา
- [Roles and Permissions](../access-control/roles-and-permissions.md): สิทธิ์และขอบเขตข้อมูล
- [User Management](../access-control/user-management.md): บัญชีและภาษาที่เลือก
- [Customer Info](../sales/customer-info.md) และ [Sales Status Flow](../sales/sales-status-flow.md): ข้อมูลธุรกิจ

## Layout structure

```text
┌──────────────────┬────────────────────────────────────────┐
│ Project Info     │ ลูกค้า                  ไทย / EN  ผู้ใช้ │
│                  ├────────────────────────────────────────┤
│ ภาพรวม           │ ลูกค้า                                 │
│ ลูกค้า           │ จัดการองค์กรและผู้ติดต่อ    [+ เพิ่มลูกค้า] │
│ งานขาย           │                                        │
│                  │ [ค้นหาลูกค้า...]  [ตัวกรอง]              │
│ การดูแลระบบ      │                                        │
│   ผู้ใช้งาน       │ พื้นที่ตัวอย่างรายการลูกค้า               │
│   บทบาทและสิทธิ์  │                                        │
│                  │                                        │
│ [ย่อเมนู]        │                                        │
└──────────────────┴────────────────────────────────────────┘
```

ภาพนี้แสดงตำแหน่งโดยประมาณ ไม่ใช่ขนาดตายตัว Sidebar อยู่ด้านซ้าย ส่วน Header และเนื้อหาอยู่ด้านขวา โดยชื่อ Project Info เป็นชื่อแสดงตั้งต้น

## Navigation

| เมนูไทย | English | เนื้อหาใน prototype | ผู้ที่เห็นเมนู |
| --- | --- | --- | --- |
| ภาพรวม | Overview | พื้นที่ตัวอย่างสรุปงาน | ทุกบทบาท |
| ลูกค้า | Customers | ชื่อหน้า ปุ่มหลัก และพื้นที่ตัวอย่างรายการ | ทุกบทบาท |
| งานขาย | Sales | พื้นที่ตัวอย่าง Opportunity | ทุกบทบาท |
| การดูแลระบบ | Administration | กลุ่มเมนู ไม่ใช่หน้ารายการแยก | Admin |
| ผู้ใช้งาน | Users | หน้าตัวอย่างภายใต้ Administration | Admin |
| บทบาทและสิทธิ์ | Roles and Permissions | แสดงบทบาทตั้งต้น ไม่เพิ่มตัวแก้ไขสิทธิ์แบบกำหนดเองในรอบนี้ | Admin |

- ผู้ติดต่ออยู่ภายในหน้าลูกค้า และ Opportunity อยู่ภายในงานขาย ไม่มีเมนูหลักแยกในรอบนี้
- ทุกบทบาทเห็นเมนูหลักได้ แต่ข้อมูลและจำนวนสรุปต้องจำกัดตามสิทธิ์ ผู้ไม่มีข้อมูลที่ได้รับอนุญาตเห็น empty state
- ปุ่มเพิ่มลูกค้าแสดงเฉพาะ Admin, Sales Manager และ Sales ตามเอกสารสิทธิ์
- เมื่อทำ prototype อาจใช้บทบาทจำลองเพื่อทบทวนเมนูได้ แต่ไม่ถือเป็นการยืนยันตัวตนหรือบังคับสิทธิ์จริง
- การเข้า URL ของหน้าที่ไม่มีสิทธิ์ต้องแสดงหน้าไม่อนุญาตโดยไม่เผยเนื้อหา การซ่อนเมนูไม่ทดแทนการตรวจสิทธิ์ Backend ในระบบจริง
- รายละเอียด route จะกำหนดหลังเลือก Framework

## Sidebar

- แสดงชื่อระบบด้านบน เมนูพร้อมไอคอนและข้อความ และปุ่มย่อ/ขยาย
- แสดงเมนูปัจจุบันด้วยพื้นหลังหรือเส้นเน้นร่วมกับข้อความ ไม่ใช้สีเพียงอย่างเดียว
- เมื่อย่อ ให้คงไอคอนพร้อมชื่อที่เข้าถึงได้และ tooltip เมนูย่อยของ Administration ยังต้องเข้าถึงได้
- หากรายการเมนูสูงเกินหน้าจอ ให้เลื่อนรายการได้โดยไม่บังปุ่มสำคัญ
- เมื่อเปลี่ยนหน้า ให้คงโครงหลักและอัปเดตเมนูปัจจุบันให้ตรงกับเนื้อหา

## Header

- ด้านซ้ายแสดงชื่อหน้าระดับปัจจุบัน หรือ breadcrumb เมื่อมีหน้ารายละเอียด
- ด้านขวาแสดงตัวสลับภาษาและเมนูผู้ใช้ ไม่เพิ่ม global search หรือ notification ในขอบเขตรอบนี้
- เมนูผู้ใช้มีชื่อแสดง บทบาท ลิงก์โปรไฟล์ และออกจากระบบ โดยโปรไฟล์เป็นหน้าตัวอย่างได้
- การออกจากระบบใน prototype เป็นพฤติกรรมจำลองที่ต้องระบุให้ชัดเจน ไม่อ้างว่ามี session จริง
- บนจอเล็กเพิ่มปุ่มเปิด Sidebar และจัดองค์ประกอบไม่ให้ทับกัน

## Content area

- ใช้ลำดับชื่อหน้า คำอธิบายสั้น ปุ่มหลัก แล้วจึงพื้นที่ตัวกรองและข้อมูล
- แต่ละหน้ามีหัวข้อหลักหนึ่งรายการที่ชัดเจน พร้อมระยะห่างสม่ำเสมอ
- หน้า Customers ใช้ข้อมูลสมมติสั้น ๆ เพื่อดูความกว้างพื้นที่และข้อความสองภาษา ยังไม่กำหนดคอลัมน์หรือฟอร์มฉบับสมบูรณ์
- ปุ่มหรือตัวควบคุมที่ยังอยู่นอกขอบเขตต้องปิดใช้งานพร้อมคำอธิบาย หรือระบุว่าเป็นตัวอย่าง ไม่ปล่อยให้คลิกแล้วเงียบ
- เตรียมรูปแบบแสดง loading, empty และ error state ให้เข้ากับโครงหน้า

## Language switching

- ใช้ตัวเลือก `ไทย / EN` พร้อมระบุภาษาปัจจุบันชัดเจน และเข้าถึงด้วยแป้นพิมพ์ได้
- สลับข้อความระบบทั้ง Sidebar, Header, ชื่อหน้า ปุ่ม เมนูผู้ใช้ และข้อความสถานะ
- คงหน้าปัจจุบัน สถานะย่อเมนู และข้อมูลที่ยังไม่บันทึกเมื่อสลับภาษา
- ข้อมูลจำลองที่แทนข้อมูลผู้ใช้ เช่น ชื่อองค์กร คงภาษาต้นฉบับ
- แยกชุดคำแปลตาม Conventions และตั้งภาษาของหน้าให้ตรงกับภาษาที่เลือก
- ภาษาเริ่มต้นและการจดจำข้าม session ยังรอกำหนด สำหรับ prototype ให้ระบุค่าเริ่มต้นที่ใช้ประกอบการทบทวน

## Visual direction

แนวทางตั้งต้นสำหรับทบทวน ยังไม่ใช่ design tokens ที่อนุมัติแล้ว

| องค์ประกอบ | แนวทาง |
| --- | --- |
| Sidebar / Header | พื้นสีขาว ขอบแบ่งบาง ๆ |
| พื้นที่เนื้อหา | พื้นเทาอ่อนและพื้นที่ข้อมูลสีขาว |
| สีเน้น | สีน้ำเงินสำหรับปุ่มหลักและเมนูที่เลือก |
| ตัวอักษร | สีเข้ม ฟอนต์อ่านง่ายและรองรับไทย/อังกฤษ |
| ไอคอน | ใช้ชุดเดียวกันพร้อมข้อความหรือ accessible name |
| สถานะ | สีร่วมกับข้อความ โดย Stage และ Status ยังเป็นคนละข้อมูล |
| ระยะห่าง | ใช้ชุด spacing สม่ำเสมอ ไม่บีบข้อความเพื่อให้พอดีเฉพาะภาษาเดียว |

## Responsive and accessibility

- จอกว้างแสดง Sidebar แบบย่อ/ขยายได้ จอเล็กเปลี่ยนเป็นแผงเมนูซ้อนด้านหน้า breakpoint จะเลือกจากการทดสอบเนื้อหาจริง
- แผงเมนูจอเล็กปิดได้ด้วยปุ่มปิด Escape หรือกดพื้นหลัง และปิดเมื่อเลือกหน้า
- เมื่อเปิดแผงเมนู ให้ย้าย focus เข้าแผง จำกัด focus ภายในขณะเปิด และคืน focus ไปปุ่มเปิดเมื่อปิด
- รองรับ Tab, Enter และ Space ตามชนิดตัวควบคุม มี focus indicator ที่เห็นได้ และลิงก์ข้ามไปเนื้อหาหลัก
- ใช้พื้นที่ navigation, header และ main ที่มีความหมาย พร้อมระบุหน้าปัจจุบันให้เทคโนโลยีช่วยเหลือรับรู้
- เมื่อเปลี่ยนหน้า ให้จัดการ focus ไปยังเนื้อหาหลักหรือชื่อหน้าอย่างเหมาะสม
- ทดสอบทั้งภาษาไทยและอังกฤษโดยข้อความไม่ทับ ไม่หาย และโครงหน้าไม่เกิด horizontal scroll ที่ไม่จำเป็น

## Acceptance criteria

- [ ] เปลี่ยนเมนูแล้วแสดงหน้าตัวอย่างที่ตรงกัน พร้อมไฮไลต์เมนูปัจจุบัน
- [ ] ย่อ/ขยาย Sidebar ได้ และทุกเมนูที่อนุญาตยังเข้าถึงได้
- [ ] บนจอเล็กเปิด/ปิดแผงเมนูได้ รวมถึง Escape และการคืน focus
- [ ] สลับไทย/อังกฤษแล้วข้อความระบบเปลี่ยนครบ โดยคงหน้าและสถานะการใช้งานเดิม
- [ ] เปิด/ปิดเมนูผู้ใช้และไปหน้าโปรไฟล์ตัวอย่างได้
- [ ] Administration แสดงเฉพาะ Admin และ Viewer ไม่มีปุ่มแก้ไขข้อมูลธุรกิจ
- [ ] หน้าที่ไม่อนุญาตไม่แสดงเนื้อหา แม้เข้าผ่านการนำทางโดยตรงใน prototype
- [ ] ใช้แป้นพิมพ์เข้าถึงเมนู ตัวสลับภาษา และปุ่มหลักได้
- [ ] ตรวจโครงหน้าทั้งจอกว้างและจอเล็กในสองภาษา พร้อมตัวอย่าง empty/loading/error
- [ ] ใช้ข้อมูลสมมติเท่านั้น และระบุพฤติกรรมที่ยังไม่ทำงานหรือเป็นการจำลองอย่างชัดเจน

## Decisions still open

- Framework และโครงสร้าง route
- ชื่อระบบ โลโก้ ฟอนต์ ค่าสี ขนาด Sidebar และ breakpoint
- ภาษาเริ่มต้นและวิธีจดจำภาษาหรือสถานะย่อเมนูข้าม session
- รายละเอียดหน้า Customers และ Sales ซึ่งจะแยกเอกสารเพิ่มเติมเมื่อเริ่มออกแบบแต่ละหน้า
