# User Management

## Scope

แนวทางตั้งต้นสำหรับผู้ใช้ภายในระบบ POC ตาม [Architecture](../architecture.md) ผู้ดูแลสร้างบัญชีให้ ไม่มีการสมัครเองหรือเชื่อมระบบผู้ใช้ภายนอก ยังไม่มีบัญชีสำหรับลูกค้า โดยแยกผู้ใช้ระบบออกจาก Contact ของลูกค้า

เอกสารนี้กำหนดข้อมูลและพฤติกรรมที่ต้องการ ยังไม่สร้างบัญชีจริงหรือเลือก library สำหรับเข้าสู่ระบบ สิทธิ์อ้างอิงจาก [Roles and Permissions](roles-and-permissions.md)

## User information

| ข้อมูล | การจัดเก็บ | รายละเอียด |
| --- | --- | --- |
| User ID | บังคับ | รหัสถาวรสำหรับอ้างอิงผู้ดูแลลูกค้า เจ้าของงาน และประวัติ |
| Display name | บังคับ | ชื่อแสดงในระบบ |
| Email | บังคับ | อีเมลไม่ซ้ำสำหรับระบุบัญชี กติกาปรับรูปแบบกำหนดตอนออกแบบ schema |
| Role | บังคับ | หนึ่งบทบาทต่อบัญชีใน POC: Admin, Sales Manager, Sales หรือ Viewer |
| Status | บังคับ | Active หรือ Inactive |
| Preferred language | เสริม | `th` หรือ `en`; เมื่อยังไม่เลือก ใช้ภาษาเริ่มต้นที่จะกำหนด |
| Created at / by | บังคับ | เวลาและผู้สร้างบัญชี กรณีบัญชีแรกระบุว่าเป็นการตั้งต้นระบบ |
| Updated at / by | บังคับ | เวลาและผู้แก้ไขล่าสุด |
| Last login at | เสริม | เวลาที่เข้าสู่ระบบสำเร็จล่าสุด |

ข้อมูลบัญชีจริงเก็บใน PostgreSQL ไม่เก็บรายชื่อ อีเมลจริง หรือข้อมูลลับใน repository หากเลือกการเข้าสู่ระบบด้วยรหัสผ่าน ต้องเก็บเฉพาะ password hash และไม่แสดงข้อมูลดังกล่าวในข้อมูลผู้ใช้หรือ log

## Use cases and lifecycle

| กรณีใช้งาน | ผู้ดำเนินการ | พฤติกรรม |
| --- | --- | --- |
| สร้างบัญชี | Admin | ตรวจอีเมลซ้ำ ระบุชื่อ บทบาท และสถานะ พร้อมบันทึกผู้สร้าง |
| เริ่มใช้งานบัญชี | ผู้ใช้ | ตั้งค่าการเข้าสู่ระบบด้วยกระบวนการที่จะเลือกก่อน implementation ไม่ถือว่าบัญชี Active ผ่านการยืนยันตัวตนแล้ว |
| เข้าสู่ระบบ | ผู้ใช้ Active | ตรวจข้อมูลยืนยันตัวตนและสถานะบัญชีก่อนอนุญาตให้ใช้งาน |
| แก้ข้อมูลส่วนตัว | เจ้าของบัญชี | แก้ชื่อแสดงและภาษาที่เลือกได้ ไม่แก้บทบาท สถานะ หรืออีเมลระบุบัญชีเองใน POC |
| เปลี่ยนอีเมล บทบาท หรือสถานะ | Admin | ตรวจข้อมูลและบันทึกค่าก่อน/หลัง ผู้เปลี่ยน เวลา และเหตุผล |
| ออกจากระบบ | ผู้ใช้ | ยกเลิก session ที่ใช้งาน |
| ขอความช่วยเหลือเข้าใช้บัญชี | ผู้ใช้ / Admin | ใช้กระบวนการกู้คืนที่จะกำหนด ไม่ส่งหรือเปิดเผยรหัสผ่านเดิม |
| ปิดใช้งานบัญชี | Admin | เปลี่ยนเป็น Inactive และยกเลิก session เดิม ปฏิเสธคำขอใช้งานถัดไป |
| เปิดใช้งานอีกครั้ง | Admin | ตรวจบทบาทและงานที่รับผิดชอบก่อนเปลี่ยนเป็น Active โดยไม่คืน session เก่า |

## Account rules

- ไม่ลบบัญชีที่มีข้อมูลอ้างอิง ใช้ Inactive เพื่อคงประวัติผู้สร้าง ผู้แก้ไข และเจ้าของงานเดิม
- เมื่อปิดบัญชี ให้แสดง Customer, Opportunity และกิจกรรมค้างที่ต้องมอบหมายใหม่ Admin หรือ Sales Manager เป็นผู้ดำเนินการ ห้ามลบหรือเปลี่ยนประวัติย้อนหลัง
- บัญชี Inactive ห้ามรับมอบหมายงานใหม่ แต่ยังแสดงชื่อในประวัติเดิมได้
- การเปลี่ยนบทบาทต้องมีผลกับคำขอถัดไป ไม่ให้ session เดิมคงสิทธิ์ที่ถูกถอน
- ต้องคง Admin ที่ Active อย่างน้อยหนึ่งบัญชี ไม่อนุญาตให้ปิดหรือลดบทบาท Admin คนสุดท้าย
- การเป็นเจ้าของ Customer หรือ Opportunity ไม่อนุญาตให้จัดการบัญชีผู้ใช้
- ภาษาที่เลือกมีผลต่อข้อความระบบตาม [Language conventions](../conventions.md#language-and-localization) ไม่แปลข้อมูลที่ผู้ใช้กรอก

## Validation scenarios

- สร้างบัญชีด้วยอีเมลซ้ำไม่ได้ และผู้ที่ไม่ใช่ Admin จัดการบัญชีผู้อื่นไม่ได้
- ผู้ใช้แก้บทบาทหรือสถานะของตนเองผ่านคำขอโดยตรงไม่ได้
- บัญชี Inactive เข้าสู่ระบบหรือใช้งานผ่าน session เก่าไม่ได้
- การลดสิทธิ์มีผลกับคำขอถัดไป และ Admin คนสุดท้ายไม่ถูกปิดหรือลดบทบาท
- การปิดบัญชีคงข้อมูลอ้างอิงเดิม และภาษาที่เลือกคงอยู่เมื่อกลับเข้าใช้ระบบ

## Decisions still open

- วิธีเข้าสู่ระบบ การตั้งค่าบัญชีครั้งแรก และการกู้คืนบัญชี โดยไม่พึ่ง integration ภายนอก
- Library สำหรับ authentication, อายุ session และกระบวนการสร้าง Admin คนแรก
- จำนวนผู้ใช้จริงและภาษาเริ่มต้น รายละเอียดการบังคับใช้จะกำหนดก่อน implementation
